# Write and revise

Draft from the supplied notes or apply voice to existing prose. For existing prose use [rewrite.md](rewrite.md) for coverage and source checks.

Infer the current medium, audience, relationship, and language from the request. Apply current instructions before confirmed preferences, supported contextual habits, and tentative tendencies. Skip unknown traits. Apply scoped habits where the context supports them.

Select the actual publisher's voice; a person's profile does not automatically govern their organization's copy. Use a supplied readable guide as-is. Consider the recipient's supplied context and the passage's purpose before scanning word choices. Reader background, writer familiarity, and how information was obtained are distinct task-local judgments; do not persist guesses as profile facts.

For a supplied draft, identify facts, entities, exact values, quotations, uncertainty, obligations, negation, purpose, and protected wording. For new prose, derive these from the brief. A brief's instructions are not all output content, so don't mechanically compare it as an original draft.

When the draft could imply knowledge, expertise, firsthand experience, or recent learning, apply [knowledge.md](knowledge.md). Make a qualified guess about familiarity only from relevant evidence. Track who supplied/researched a fact separately from whether the writer already knew it. Unknown familiarity usually calls for neutral wording, not extra hesitation or invented “I just learned” narration.

Preserve reliable irregularities by default. Follow ordinary instructions such as “fix obvious grammar slips” or “make it suitable for a client.” Keep confirmed preferences and dialect features when cleaning up a draft. When the audience or medium changes, carry over the traits supported in the new context.

Use natural frequencies. Occasional fragments, “like,” or spelling quirks do not belong in every sentence. A short output may have no relevant opportunity for a known irregularity. Do not insert random errors to make smooth prose appear human. If an ask-policy trait matters materially, ask; otherwise omit that uncertain feature without claiming resolution.

## Match examples to the section

Use the section heading and the job of the prose. An introduction establishes the task or question. Methods explains what was done and why. Results reports observations and their limits. A troubleshooting account connects a problem, the check or fix, and what happened next. A reflection links the work to a takeaway.

Choose up to two short examples per section in the matching voice context. Prefer explicit section examples in the profile, then eligible excerpts from available samples whose purpose matches. Rank the section's purpose ahead of topic words. Use individual examples when writing as one person. Use user-selected group examples for a report in the group's voice. Exclude held-out pieces, duplicates, templates, and unattributed excerpts. When evidence is scarce, use the applicable profile habits.

Read the examples and supported structure habits for what the writer puts first and how they follow it up. Use that order when it fits the current audience, section purpose, and edit scope. If a habit does not fit, use the order the reader needs. Build each paragraph from the current facts and their relationships. Keep sample wording and sample facts out of the new text. Apply the [editorial review](editorial-review.md) during drafting and at delivery.

For substantial or difficult work, internally compare source-close and voice-forward drafts. One draft is sufficient for a routine short message. Favor recognizable voice with minimal unsupported semantic movement.

Before finalizing, fix justified editorial findings, including any generic phrasing introduced while matching the profile. Preserve the writer's effective repetitions and rough edges. Verify certainty, commitments, negation, and other source details, and check for invented facts, experiences, relationships, or leaked anecdotes. An audit-only request calls for findings.

## Checking and output

Use check with --source only for an actual original draft. Repeat --protect for literal names/strings that must survive. --manifest enables long phrase-overlap checks. Optional --author-context accepts the user's explicit current-task statements about their own knowledge/experience; it is not a place for retrieved articles or raw style samples. Narrow English heuristics flag newly introduced personal knowledge/experience/learning claims for review, not automatic removal. The tool cannot catch all paraphrased source facts or establish meaning equivalence; review those manually.

Only matching-context/mode mechanical rules apply. Missing context is a review issue. Resolve blocking findings before delivery; judge review findings instead of blindly rewriting. Do not force a favorite word or typo into every draft merely to satisfy a checker.

Without tools, do the same review manually. Return requested prose directly. Include a brief limitation only when thin or mismatched evidence materially affects the result. Keep local corrections local and reusable preferences scoped; never store one author's profile inside the installed skill.
